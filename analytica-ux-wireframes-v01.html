0 · Flow diagram

The full journey. Cases enter from two streams — detected by Analytica and submitted by marketers — get ranked into one hit-list, and each is worked through the five-stage pipeline to a solution. The Analyst narrates every stage; the AI toggle floats over the whole case.

  1. Two streams, one list. System-detected cases and marketer-submitted cases merge into a single money-ranked hit-list — the "where to focus" answer.
  2. Decide is a fork, not an end. Approve moves the case to the Verify watchlist; Dismiss asks for a reason and routes it (resolved / snoozed / feedback) instead of dropping it.
  3. Upload is a lens, not a page. Loading CSVs re-renders the whole flow on merchant data; the structure never changes.

  1. The Analyst narrates the peeling. Each revealed layer gets a one-line verdict in the narration — the star moment of the demo.
  2. Layers rule things out, in order. Traffic → location → cost → cause. The marketer feels the funnel narrowing, like a real investigation.
  3. Click-to-peel is the core interaction. The dashed "peel" button is deliberately tactile — the marketer does the detective work, the Analyst interprets.
  4. Culprit card names names. Rules-detected, badged as such — the demo never pretends a model found it.
  5. Heuristic honesty is a feature. The checklist is labeled heuristic with an explicit footnote: data pinpoints where, confirming which cause takes a look. This builds trust with data-driven marketers.

  1. The Analyst recommends, the human decides. The narration frames the plan as a recommendation awaiting approval — agency stays with the marketer.
  2. Sequenced, timed steps are the second "where to focus" answer: what to do first, second, third — with timing pills (today / 48h / this week / 7 days / gated).

  4. Dismiss is a fork, not a dead end (proposed, from review 2026-10-11): one-tap reason → resolved log, snooze with re-surface condition, or disagreement captured as training signal for the intelligence layer.

8 · Edge states

The trust-relevant states. All exist in the demo and were verified; they matter because a product that handles failure gracefully earns the marketer's confidence.

various
Detect · all quiet✅ All quiet — no drops, leaks, or offenders. "This feed lights up the moment something moves."1
Upload · parse errorsCouldn't load — per-file errors listed (missing column, invalid value). Row counts and warnings shown separately from hard errors.2
Analyst · live failureLive narration failed (…) — showing the rules version. The fallback is visible, never silent.3
Decide · snoozed case (proposed)"Not now" → leaves the hit-list; re-surfaces automatically if the metric worsens. The snooze has a condition, not just a timer.
  1. All-quiet is a designed state, not an absence — it tells the marketer the system is watching, which is the whole value proposition on a good day.
  2. Errors name the file and the problem. The uploader was hardened for real merchant exports; the wireframe keeps errors and warnings visually distinct.
  3. Fallbacks are visible. Rules narration, sample-data badges, heuristic labels — the demo never fails silently. This is a product principle, not a detail.
